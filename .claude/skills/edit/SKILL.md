# edit：Claude 剪辑与审片

各拍渲染完成后，流水线会自动出一版时间线 `edit_timeline.json`，用的是现有的剪辑 v2 算法：快慢交替下刀、刀口吸到分句、换章 whip、配乐踩点。这一版就是**初稿**，你在它上面改画面。

- 刀口和节奏跟着旁白走，一般不用动。
- 你主要做的是**每一刀用什么画面**。
- Claude 项目不会逐刀发取材请求。初稿只按排序取材，挑画面靠你看图钉选。

刀号写成 `拍号:第几刀`，比如 `3:0` 是第 3 拍的第一刀。

## 循环
```bash
python -m app.cli edit check <pid>                    # 体检:对题率、重复、静图占比、兜底
python -m app.cli edit sheet <pid> [--beats 3-7]      # 刀表拼图(每刀一格)→ Read 看图
python -m app.cli edit candidates <pid> 3:0 [--pages 2]   # 这一刀的候选(每页 6 个)+ 拼图
python -m app.cli edit pick <pid> 3:0 <item_id> [<item_id> ...]   # 钉选,按顺序拼接
python -m app.cli edit put <pid> pins.json            # 批量:{"pins": {"3:0": ["id"]}, "unpin": ["5:1"]}
python -m app.cli edit unpin <pid> 5:1                # 放开,回到自动取材
python -m app.cli edit preview <pid>                  # 当场渲整片预览(几分钟,Bash 后台跑)
python -m app.cli review <pid> [--qa]                 # 一页看全;--qa 出逐帧联系表 + 音频检查
```
批量改动用 `put` 一次提交：每钉选一次都要重编一遍时间线。钉选全部改完，再跑一次 `preview`。

## 挑画面的标准（看拼图时逐条过）
1. **观众要能"看到这半句在讲什么"**。讲后排就给后排，讲充电口就给充电口特写。候选里标了"对题"的优先，但最后以你看图的判断为准。
2. **是这台车**：车型、年款、颜色和片子里其他刀一致。拿不准的不用。
3. **不要配错特写**：讲 A 部件时出现 B 部件的特写，观众会以为在讲 B。
4. 同一素材全片最多用 2 刀，相邻刀不要同一个视角。
5. 开头 3 秒用大镜头、动起来的车。开头和结尾只能用确认是本车的一方素材（钉选时会拦）。
6. 视频优先。静图占比过高会被门禁 B 拦（机构拆解片除外）。
7. 一刀的时长是定的。视频不够长就接第二段：`pick 3:0 idA idB`。

钉选会做硬校验：可用、授权允许当背景、无主持人、开头结尾只用一方素材、时长铺得满。过不了的整批拒收，读 `error` 换一个。之后改稿或重配音导致某一刀的半句变了，这一刀的钉选会自动作废，`edit check` 里能看到。

## 放行前的自审
1. `edit check` 的 error 清零。对 warning 逐条判断：要么改掉，要么说得出为什么留着。
2. `edit sheet` 全片过一遍，没对上题的刀要么换，要么确认确实没有更好的素材。
3. `edit preview` 渲染完后跑 `review <pid> --qa`，用 Read 看报告和联系表：黑场、闪帧、字幕压字、竖屏安全区、响度、静音。
4. 音频问题看 **voice** skill。整拍画面坏了用 `rerender <pid> <拍号>`，重渲完会回到门禁 B，钉选会放掉。
5. 把这些交给用户：预览路径、改了哪几刀（为什么改）、留着的 warning、降级记录。用户在对话里同意之后才执行 `step <pid> --confirm`。

## 规矩
- `swap <pid> <key>` 是"排除现在的素材，按排序换下一个"，不看图。能看图就用 candidates + pick。
- 不要改 `edit_timeline.json` 文件本身，所有改动都走命令，这样刀口、配乐踩点、使用记录才会一起重算。
- 剪辑节奏（快慢交替、吸拍、章节 whip）是全局风格，不在单片里改。用户觉得节奏不对，就记下来反馈给用户，不要手改。
