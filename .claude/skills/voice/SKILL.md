# voice：配音导演

旁白在 ASSETS_READY 之后由方舟豆包 TTS 2.0 合成。相邻句子会一口气合成一条，再按句切开，这样句与句之间的语气是连着的。每拍的时长取决于旁白实际有多长。

```bash
python -m app.cli voice <pid>        # 时长、字数、实际语速、语音质检结果、警告
```

## 看什么
- `qa.errors`：重合成以后仍然不合格的句子（从 1 开始数），常见原因是哑句、截断、错位。门禁 A 会拦。
- `qa.findings` 里 `level=suspect` 的是可疑句，`heard` 是转写出来的内容。拿它和原文比：差了字、多了字、读成了别的词，都要处理。
- `chars_per_second`：横屏实测大约 6.0，竖屏大约 4.7。明显偏离说明语速设置或断句有问题。
- `warnings`：没装 faster-whisper 时只做了信号检查，不能确认念得对不对，这一点要告诉用户。

## 发现问题怎么办
- **念错字、多音字读错**：改稿最有效。在门禁 A 的 `script-put` 里换一种说法，或者换个词（"行"读成 háng 就改写）。字幕用原文，TTS 用 `normalize_for_tts` 转出来的读法，数字会自动转。
- **个别拍的声音坏了**：门禁 B 时 `python -m app.cli rerender <pid> <拍号...>` 重渲那几拍。
- **整体太快或太慢**：语速是全局设置（`TTS_SPEED`），由用户决定，不要自己改 `.env`。
- **停顿**：不要把停顿全压掉，听起来会像憋着气。只处理过长的停顿。
- 自审时可以用 ffmpeg 把某一拍的音频切出来，交给用户试听，例如 `ffmpeg -ss <起> -t <长> -i <narration_path> clip.wav`。
