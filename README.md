# aimovice

**本地运行的产品解说视频工厂**(汽车、母婴,其它品类按 YAML 加)。输入一个车型 / 产品型号,自动产出 16:9 横屏、2–8 分钟的信息型解说长视频,
对标「三驱兄弟」式的做法:官方宣传片 / 实拍只当背景,信息靠叠加层(参数面板、大字关键词、
数据卡、大数字、章节条)传达。

```
选题 → 事实采集 → 解说脚本 → 逐拍版式 → [人工门禁 A]
    → 旁白 TTS(定每拍时长) → 逐拍渲染 → [人工门禁 B] → 拼接混音 → 成片导出
```

不调视频生成模型:花钱的只有 TTS、BGM、几次 LLM,以及每台车一次性的素材池打标签。

> 竖屏(9:16)的 H3 逐镜头生成链路已于 2026-10-20 删除,需要时可从 git 历史找回
> (删除前最后一个包含它的提交是 `9b7e42f`)。

## 快速开始

### 1. 依赖

| 组件 | 状态 | 说明 |
|---|---|---|
| Python 3.12 | 必需 | |
| Python 依赖 | 装一次 | 清单在 `pyproject.toml`(单一来源):`pip install -r requirements.txt` 装运行时依赖,`pip install -e ".[dev]"` 连测试工具(pytest / ruff / mypy)一起装 |
| ffmpeg | **必需** | 已安装于 `C:\ffmpeg\bin`,不在系统 PATH,在 `.env` 里指定 |
| M Plan 订阅 Key **或** `mcode-tools` CLI | 二选一 | 语音、音乐、图片理解、网络搜索的通道。订阅 Key 填 `.env` 的 `MINIMAX_PLAN_KEY`,任何终端可跑;`mcode-tools` 只能在 MiniMax Code 里跑 |
| node 22+ + HyperFrames | 可选 | 概念动画(`concept` 版式)。在 `motion/` 下 `npm install`(版本锁在 `motion/package.json`);渲染用本机 Chrome / Edge,找不到时在 `.env` 配 `HYPERFRAMES_BROWSER_PATH`。没装就退回数据卡 |
| yt-dlp | 必需 | 素材池从 B站 / YouTube / TikTok 拉素材,YouTube 还需要 PATH 上有 node 或 deno |
| playwright | 发布/监控用 | `pip install playwright`。只给小红书 / 视频号 / 抖音网页版兜底的浏览器自动化用;**浏览器复用本机 Chrome / Edge,不必 `playwright install`** |

### 2. 配置

```bash
copy .env.example .env
```

编辑 `.env`,**至少填入 `DEEPSEEK_API_KEY`**(事实抽取、脚本与逐拍版式依赖它)。其余项均有合理默认值。

| 变量 | 默认 | 说明 |
|---|---|---|
| `MEDIA_PLATFORMS` | `bilibili,youtube,tiktok` | 素材池找源的平台及优先级 |
| `YTDLP_PROXY` | 空 | yt-dlp 代理,国内访问 YouTube / TikTok 需要,如 `http://127.0.0.1:7890` |
| `YTDLP_COOKIES` | 空 | 浏览器导出的 `cookies.txt`。B站高清 / 抖音下载需要 |
| `USE_LIBRARY` | `1` | 是否启用素材池(背景画面全部来自它) |
| `LIBRARY_BUILD_BUDGET` | `1800` | 素材池一次构建的时长预算(秒),`0` 不限 |

### 3. 启动

```bash
python run.py            # http://127.0.0.1:8848
```

**长时间运行请用脱离托管的启动方式:**

```bash
powershell -ExecutionPolicy Bypass -File scripts\serve.ps1 -Port 8848
```

直接 `python run.py` 时,进程是托管后台任务的子进程,托管任务有 1 小时上限,到点会把服务一起收走。
`serve.ps1` 用 `Start-Process` 起独立进程,输出写到 `data/logs/server-*.log`。
(`serve.ps1` 刻意只用 ASCII:Windows PowerShell 5.1 按 ANSI 读无 BOM 的脚本,中文会把解析搞挂。)

首页会显示环境自检:ffmpeg、接口通道、LLM 三项全绿才可完整跑通。

### 4. 跑第一条视频

1. 首页填车型(如 `小米YU7`)→ 选时长(目标值,成片跟着旁白走)→ 创建。
2. 自动跑完**事实采集 → 脚本 → 逐拍版式**,停在**门禁 A**;同时后台开始建这台车的素材池。
3. 检查事实、脚本、分镜,可直接编辑。**改完保存会立刻跑一遍预审**(见下"门禁 A 预审"),
   并把改动同步进分镜 —— 旁白以分镜为准,不改分镜就等于没改稿。
4. 确认后先合成全片旁白,每拍时长 = 它那几句的实际时长,然后逐拍渲染。
5. **门禁 B** 审渲好的各拍,不满意的点「换背景重拍」。
6. 确认后直接拼接、混入旁白与 BGM、烧字幕,产出 `output.mp4` 与 `cover.jpg`。

### 门禁 A 预审(机器先查,人再看判断题)

门禁 A 是最后一道人工确认。**机器查得出的错不该靠眼睛一条条找**,所以保存脚本时
会跑一遍 `compliance_lint`,结果直接显示在脚本页上:

- **必须改(error)**:不放行。点「确认 A」会被拦下,提示还剩几处、分别是什么,
  改完再确认即可。确实要带着问题往下走,弹窗里选「仍然继续」(`force`)。
- **提醒(warning)**:不拦,但值得扫一眼。

预审覆盖的机械判据(详见"合规检查"):

| 判据 | 级别 | 为什么 |
|---|---|---|
| 开场第一句是套话("大家好""朋友们好""今天聊…") | error | 黄金三秒不能自我介绍 |
| 开场第一句超过 18 字 | error | 3 秒读不完就没有钩子 |
| 空洞评价("很猛""闭眼入""吊打") | error | 是拿不出论据时的偷懒,必须换成"比什么、好在哪" |
| 对比章节拿厂商口径当论据("卢伟冰说…多数消费者选了它") | error | 那是替厂商站台,不是评测结论 |
| 段落含数字但没有事实引用 | error | 编造数据 |
| 引用了不存在的事实 ID | error | 出处断了 |
| 品类禁用词 / 广告法绝对化用语 | error | 投放会被拒 |
| 同一条事实被多个章节反复引用 | warning | 这几段是不是在重说同一件事 |
| 同一个数字在 3 段以上反复出现 | warning | 价格复读 |
| 数字没带口径 / 该讲原理的段落没讲原理 | warning | 深度不够 |

只有**开场段**才套黄金三秒的规矩 ——「使用成本」「品牌历史」这类方向的第一段
本来就不是钩子,套上去是误伤。

### 脚本改动会同步进分镜

旁白轨是按**分镜**里的 `narration_zh` 合成的,不是按 `script.json`。
所以在门禁 A 改完脚本保存时,会同步把新旁白写回分镜(`explainer.sync_narration`),
并按新旁白**重新核对**依赖旁白的叠加数据:

- `highlight` / `hook` 的大字重新核对:照抄旁白的丢掉,引用了已删数字的丢掉;
  两行都丢光 → 这一拍退回 `broll`
- 版式、参数面板、数据卡这些是按**事实**核过的,不受旁白改写影响,原样保留

不改这一步的话,在门禁 A 改的稿根本进不了成片 —— 改完看着像生效,成片还是旧词。

## 脚本怎么写

### 开头三段式(`script_gen.SYSTEM` 第 10 条 + 品类 YAML)

复盘给的留存结构,直接写进了提示词和段落表:

| 时间 | 段落 | 干什么 |
|---|---|---|
| 0–3 秒 | `开场` | **先给冲突**:一句带判断的反常识话,不是「XX 值不值得买」这种平的问题(第一句 ≤ 18 字,`hook_lint` 拦) |
| 3–10 秒 | `兑现承诺` | 立刻把上一段抛出的那个数字摆出来,不许绕 |
| 10–15 秒 | `亮出出处` | 一句话说明每个数字都能查到出处,全片只说这一次 |

三段共用章节「开头」,章节条上还是一章。`auto_long` 与 `baby_long` 的段落表各多这两个块
(weight 各 1,`remainder: false`:铺垫段落取 floor 就够,补位名额留给内容块),
最短时长 120 秒(15 拍)也放得下。

### 结尾要给行动(`script_gen.ending_lint`)

结尾只有总结等于没结尾。最后一段必须有一句提问(「你在纠结哪款?评论区说」)
或一句下期预告 —— 评论区互动和连看都靠这一句。缺了报 warning。

### 一段 = 一拍,拍不能太长(`script_gen.split_segments`)

一段脚本 = 一拍 = 一个版式。段落太长,这一拍里就只剩一张画面撑着(实测成片 24 拍平均
8 秒一拍,后半程好几拍是同一张参数面板杵着不走)。所以段落生成后按句末标点拆开,
一句太长再拆到逗号,**每拍不超过 28 字**。拆完落在句尾的半个逗号换成句号 ——
字幕末尾挂逗号不像话,TTS 也需要一个明确的断句。

## 画面怎么做

### 版式(`pipeline/explainer.py`)

一拍 = 一段旁白 = 一个版式:

| 版式 | 画面 |
|---|---|
| `broll` | 全屏这台车的宣传片 |
| `panel` | 宣传片 + 左侧参数面板(浅底 HUD 规格页,见下"HUD 版式") |
| `highlight` | 宣传片缩成小窗 + 两行大字关键词 |
| `card` | 整屏数据卡(spec / compare / bars / timeline),柱子生长、左右两列交替亮起等本地动画 |
| `stat` | 宣传片压暗 + 中央一个大数字从 0 滚到目标值 |
| `concept` | 概念动画(HyperFrames 渲染 `motion/scenes/*.html`,玻璃拟态风格):压在这一拍的实拍上,左侧毛玻璃数据卡 + 右侧示意图(电池包、补能、速度表、激光雷达、芯片、尺寸线稿、对比条)。品类在 `vocab.concept_scenes` 里声明可用模板 |

- 面板、卡片、大数字的每个数字都逐行核对事实(`cards.ground`),核不过就退回 `broll`;
  大字里的数字、英文型号必须在旁白或事实里出现过。
- 节奏约束:不连续两拍 `stat` / `concept`,`concept` 全片最多 6 拍;
  全片 `broll` **不超过三成**(`enforce_rhythm` + 提示词口径 + 兜底面板,见下"节奏硬约束")。
- `broll` 拍自动轮换样式(`assign_broll_styles`):全屏 / 左上角「车名 · 章名」角标 / 2–3 栏分屏依次滑入。
- 拍内各段之间 xfade 转场(0.3 秒,6 种轮换);静图运镜 8 种,按片段散开挑且不与上一刀相同;
  每章第一拍开头叠 1.2 秒章节标牌(「02 外观内饰」色条擦入)。
- 概念动画的图形(刻度、曲线、线稿)只是示意,屏幕上的数字同样只来自核对过的事实;
  按 (模板 + 数据 + 时长 + 实拍底) 缓存在 `data/_cache/motion/`,一段 6 秒约 15–20 秒渲染。
- 底部章节条常驻(按段落的 `chapter` 分章,当前章高亮),直接烧进每一拍。
- 卡片与大数字都是 PIL 关键帧 + ffmpeg concat 渲染,不依赖任何生成模型。

### HUD 版式(`pipeline/hud.py` + `overlays.panel`)

左侧参数面板的默认外观 = `motion/bakeoff/C.html`(风格 C · 极简科技 HUD)那套语言:
**浅色工程图纸 + 发丝网格 + 等宽数字 + 橙色强调 + 取景框角标**。

为什么换掉原来的深色半透明玻璃卡片:那套「宣传片铺底 + 左侧深色参数面板」是
「三驱兄弟」那批号做成的品类惯例,满屏都是 —— 复盘的原话是「越像他,越不会被记住」。
HUD C 是本片自己的视觉识别,完成度比现有叠加层高一个维度,直接拿来当面板。

具体长这样(1920×1080,左三分之一):

- **纸面** `#eceee9`,墨色 `#12161a`,次级灰 `#5d656e`,强调橙 `#ff5a1f` —— 与
  `motion/bakeoff/C.html` 一字不差(`hud.py` 顶部有对照表)。
- **顶部标签行**:左边「车名 · SPEC/SHEET」(等宽字体 + 0.14em 字距),右边「可查出处」。
  后者是本片唯一抄不走的本事,直接摆在这行最显眼的位置。
- **大数字**:等宽粗体(Consolas;装了 JetBrains Mono 就优先用它),单位小一号灰字、
  基线对齐,和 bakeoff C 的「835 km」同一种写法。中文走系统黑体 —— 等宽字体没有汉字,
  直接画会出现豆腐块。
- **每行参数**:参数名右边压一行口径小标签(「官方 | 标准版」),和数字一起被看到。
- **底部**:装饰刻度尺 + 来源行(口径 + 来源类型 + 采集月份)。刻度尺是纯装饰,
  间距固定,不表示任何数值,不给观众"这是进度条"的错觉。
- 整条叠加层的强调色(章节条当前章、大数字、角标、章节标牌)统一到这套橙。

⚠️ 纸上所有淡色(网格、分隔线)都是**预先混好的实色**,不是低 alpha 的墨色:
PIL 的 `draw` 直接写像素、不做 alpha 混合,直接画 alpha=18 的墨色等于在纸上
戳了个近乎透明的洞,叠到画面上就成了黑线(`tests/test_hud.py` 有这条回归)。

### 手机端可读性(`timeline.format_ass` / `overlays.chapter_bar`)

成片是 1920×1080 烧进平台后按手机屏宽缩放,45px 的字到手机上约等于 10px。

- **字幕**:字号 `h*0.042` → `h*0.056`(1080p 即 45 → 60px),并加了**半透明底条**
  (ASS `BorderStyle=3` 盒子模式,填充色走 `OutlineColour` = 50% 透明黑);
  底边距 `h*0.14` → `h*0.115`,给章节条让出位置。
- **章节条**:条高 `BAR_HEIGHT` 0.05 → 0.068H,字 `bar_h*0.52` 之外再钉一个下限
  `BAR_FONT_MIN = 34`(条加高后按比例算反而偏小)。
- 两者加起来 0.115H + 0.068H = 0.183H,字幕与章节条不打架。

### 背景取材(`library.fill`)

从车型素材池挑干净片段连拼,2–4 秒一刀,不要求画面对上旁白。排序:干净的视频 → 官图 →
带烧录字幕的段(裁掉底部 22% 后放大铺满)→ 用过的 → 有主持人的。跳过黑场和源片开头的淡入。

防重复:用量按**近重复簇**算(代表帧 dHash 汉明距离 ≤ 10,跨来源;同角度的几张官图用掉一张就当整簇用过);
最近 6 刀里出现过的簇、和上一刀同视角的往后排(全片共享,存 `beats_recent.json`)。
数据卡底图按拍号在去重后的主视角官图里轮换。

### 背景不许配错细节(`library._detail_conflict`)

**特写是很抢戏的画面**:观众会以为屏幕上那个部件就是正在讲的东西。旁白讲碳陶刹车,
背景却是一个车门把手特写 —— 观众的注意力被带跑,讲的东西反而没听进去。

所以这一拍会做一次**细节冲突**判定:

- 旁白里点名了某个部件(`vocab.detail_types`:刹车 / 车门 / 车轮 / 中控屏 …)时,
  背景**不能**是别的部件的特写 —— 池子剔完还够铺满就整类剔掉,不够才退回降权排序
  (宁可配得不对,也不要这一拍没有背景);
- 反过来,讲车门时,门把手的特写会被**优先选中**(它比静图默认高一档);
- 描述里认不出是哪个细节的素材不拦(不能靠猜),整车 / 全景也不构成冲突。

细节词表随品类走:`auto_long` 是刹车 / 车轮 / 车灯 / 车门 / 座舱 / 充电,`baby_long` 是
刹车 / 轮组 / 推杆 / 座舱 / 篷 / 安全带 / 折叠 —— 各自一份,互不串味。

### 素材池(`pipeline/library.py`)

**先攒、再切、再看、最后铺**:

1. **攒**:按车型自动发现源(品牌官方号、宣传片、实拍;B站 + YouTube + TikTok 官方号,口播类不要),
   加上手动贴的链接和汽车之家官图;
2. **切**:ffmpeg 场景检测,在原片自己的剪辑点切段;
3. **看**:每段抽中间帧问一次视觉模型,LLM 转成标签(视角、是不是这台车、字幕 / 海报等问题、一句话描述)。
   省钱措施:每个源先看 8 段,废段率 ≥ 70% 就跳过这个源的其余段;可用背景攒够 240 秒就停;
   同源里画面几乎一样(dHash 距离 ≤ 6)的段直接继承标签。

池子按车型存在 `data/library/<车型>/`,**跨项目复用**。构建是增量的、有时长预算,超时停在当前进度,下次接着做。

```bash
python -m app.pipeline.library build 小米YU7 --brand 小米      # 手动构建 / 续建(--category baby_long 换品类)
python -m app.pipeline.library add 小米YU7 <链接> [<链接>...]   # 加自动搜不到的好素材(抖音只能走这里)
python -m app.pipeline.library add-images 好孩子口袋车 <图片地址|本地图片|详情页链接>... --category baby_long
                                                               # 手动加图;京东 / 天猫页反爬抓不到时,把图存本地再加
python -m app.pipeline.library show 小米YU7                      # 统计:源、段、各视角可用数、视觉调用次数
python -m app.pipeline.library sheet 小米YU7 [--usable]          # 导出联系表,人工过一遍标签
```

画面质量的上限是素材池:标错车型的片段会被当背景用,建池后先看一眼联系表。

### 旁白与 BGM(`pipeline/narration.py`)

- TTS 逐句缓存在 `data/_cache/tts/`(按模型、音色、语速、文本取 key):门禁 A 改几句稿子再确认,
  只为改动的句子付钱。
- BGM 按 `music_prompt` 建共享曲库(`data/_cache/bgm/`,每个 prompt 最多 3 首),按项目轮换;
  生成失败时退回库里任意一首。

### 封面(`narration.make_cover`)

封面是唯一决定点击率的一帧。之前有两个硬伤,都改掉了:

1. **底图不再从成片抽帧**。抽出来的那一帧上带着章节条、字幕、大字,再压上标题就是
   三层字叠在一起。现在优先用素材池里的干净官图(`library.cover_still`):
   整车完整、无烧录字、认得出是这台车;**白底棚拍图最优** —— 它没有第三方角标水印
   (汽车之家那类图库图带水印,发出去等于替别人打广告),还给标题留出了干净的底。
   判据是四边取样:边缘够亮且颜色均匀 = 棚拍白底图。抽帧只作为没有官图时的兜底,
   兜底时会把底部的章节条裁掉。
2. **标题不再 `title[:14]` 硬截断**。之前"小米YU7 值不值 值得买吗"会被砍成
   "小米YU7 值不值 值得",砍在词中间,观众看到的是半句话。现在按像素宽度
   **自适应缩排**:在 92→40px 的字号里挑最大的那个,排成不超过两行;实在放不下
   才用省略号收尾。

版式:左下角强调色竖条 + 角标(主体 · 入门价)+ 大标题 + 副标题。
**入门价从事实层取**(`explainer._price_of`,取最低的那条,`low` 置信度不上屏),
**副标题用主论点**而不是"X分X秒 · 品类名"—— 主论点是全片那句判断,放在封面上
就是一句完整的钩子。浅底(白底棚拍图)自动换成深色字,不然白字压在白底上等于没有标题。

### 语音质检(`pipeline/voice_qa.py`)

确认门禁 A 合成旁白后,每句音频自动核对,不靠人听:

1. **信号检查(全部句子,纯 ffmpeg)**:哑句、整句过轻判错;语速偏离全片中位数的标「可疑」。
2. **转写复核(只对可疑句、缓存命中句、补跑句)**:faster-whisper `base`(CPU,int8)转写后看这段音频
   "更像脚本里的哪一句"——错位的音频念的是邻句。模型按需加载、用完释放;没装(`pip install faster-whisper`)
   就只做信号检查,报告里写明。核对过的缓存句有标记,下次命中不再转写。

不合格的句子清缓存、自动重合成(最多 `VOICE_QA_RETRY_ROUNDS` 轮),仍不合格拦在门禁 A,
报告写进 `voice_qa.json`。`VOICE_QA=0` 关闭。

### 节奏硬约束(`pipeline/rhythm.py`)

复盘要求:「每 5–6 秒必须有一次画面变化,且全片 broll 占比从四成压到三成以内」。
两条都做成了可测量的指标,体检结果写进 `rhythm.json`(门禁和前端都能看)。

**画面变化 = 信息层的变化**:换版式 / 进大字 / 进整屏卡片 / 进概念动画。
「换镜头」单独统计、**不算**进这条约束 —— 实测背景本来就每 2.4–3.7 秒一刀
(`library.fill` 按 4.5 秒一刀拼),把它算进来会让指标永远合格,等于没有指标。
观众感知到的「画面变了」是叠加层换了,不是底图换了。

**broll 占比给两个口径**:拍数(审片的人一眼能数)与秒数(观众占的是时间)。
两个口径都超三成才算超标。

怎么落到片子上:

1. **拍长就拆**(`script_gen.split_segments`):段落按句末标点拆,一句太长再拆到逗号,
   **每拍不超过 28 字**(按实测 TTS 语速 4.8 字/秒 ≈ 5.8 秒)。拆开的每一段保留原来的
   段落名、车名和事实引用 —— 数字还得有出处。
2. **提示词改口径**(`explainer.SYSTEM`):原来写着「全片大约四成是 broll」,现在写
   「不超过三成」,并把**每一拍自己的事实**摆到它面前(「本拍事实:…(f_xxx)」)——
   实测九成 broll 是模型猜不准哪条参数属于哪一拍才选的,给了它就不用猜。
3. **核对失败先救回,不要直接退 broll**(`explainer._ground_beat`):只剩一行的面板改成
   大数字或一行面板;大数字 / 卡片 / 概念动画核不过时,用同一批核对过的行改成左侧面板。
4. **还有 broll 的,用脚本引用过的事实兜底**(`explainer.rescue_broll`):事实里的数字在
   这一拍旁白里说过才拿来做面板 —— 数字对得上 = 这一拍真的在讲这条事实,不会把别的参数
   安到这一拍上。纯观点的拍(旁白里没有数字)老老实实留 broll。
5. **降级优先改面板**(`explainer._demote`):连续卡片 / 连续大数字这类降级,先把已核对的
   数据改成面板,实在没有才退回 broll。
6. **素材池不够时也别冻帧**(`library.fill`):池子铺不满这一拍时,拿干净的官图补几刀
   (配不同运镜),而不是把最后一帧冻到底 —— 冻帧就是一段没有画面变化的时间。

### 概念动画下限(`explainer.concept_min` / `promote_concepts`)

复盘说:概念动画是全片视觉质量最高的部分(电池包格子图、补能曲线、尺寸线稿这类
"看不见的东西"只有它讲得清),但实测一部片只用了 2–3 段。现在按拍数给下限:

    下限 = min(6, max(3, round(拍数 × 0.13)))     # 15 拍→3,30 拍→4,45 拍→6,60 拍→6

不够时由 `promote_concepts` 把 `panel` / `card` 拍升级成概念动画(数字仍来自已核对
过的事实),三条规矩:

- **不覆盖 `stat`** —— 大数字是模型特意选的,不是兜底用的;
- **不连着两拍都升级**,也不动 `sections` 里没有 concept 的段;
- 概念动画的模板必须**命中关键词才配**(`vocab.concept_scene_keys`:battery / charging /
  accel / lidar / chip / dims)—— 配错图等于把画面讲错,一个都没命中就不配。

### 每个数字都标口径(`cards.basis_tag`)

参数面板、大数字、数据卡的每一行,数字旁边都跟一个口径标签(「CLTC · 标准版 | 官方」),
底部再压一行来源行(口径 + 来源类型 + 采集月份)。这是本片唯一抄不走的本事:参数号编数字,
每个数字都能查到出处。

数据卡以前只画底部来源行、行上不标口径(漏画),现在补上了 —— 懂车的观众判断一个数字
靠不靠谱,看的就是这一行。

## 事实与合规

### 事实可追溯与分层

每个数字型陈述必须携带 `fact_refs`,否则被合规 lint 直接拦截。每条事实都带来源工具、查询串与取数日期。

| 层级(`Fact.scope`) | 含义 | 典型内容 |
|------|------|----------|
| `company` | 公司工商与财务 | 注册资本、法定代表人、证券代码 |
| `product` | **产品参数** | 续航、加速、售价、配置、电耗 |
| `industry` | 行业与市场 | 渗透率、销量排行、政策 |

- iFinD 与企查查只覆盖公司层面,车型参数来自 `ifind.product_news` 的新闻语义检索;产品向查询串要单独一条,
  混在财经查询里会被拉回公司新闻。
- 新闻有时间陷阱:超过 12 个月的参数必须注明年份并降为 `low` 置信度。
- 方向所需层级的事实少于 3 条时,界面横幅提示 `product_gap`,请在门禁 A 手动补充。
- **`fact_sources` 是方向级的**:之前 `buyguide` 方向把 `ifind.compare_news` / `ifind.cost_news`
  配在 `fact_queries` 里,被主题级覆盖挡住,**从来就没执行过**。现在这两个来源配进了
  方向的 `fact_sources`,竞品参数和用车成本才真的采得到。

### 竞品对比事实(`Fact.compare_with`)

讲一台车值不值,一半的功课在**它跟别人比**。对比事实是这么组织的:

- 一条事实**同时写清两台车同一维度的取值**(「A 售价 23.35 万,B 售价 28.9 万」),
  不是两条各说各的。数据卡的 compare 行只允许引一条事实,两个值都得在这条原文里。
- `Fact.compare_with` 标出"这条讲的是本车和它"的对比。它是**竞品对比段专用的料**:
  非对比段引用它即 lint 拦下(`facts_for` 也按段落过滤一遍),混进本车参数面板
  等于把别家的数字安到本车头上。
- 抽取时**只讲别家、句中没本车**的事实直接丢弃 —— 那种料进了本车段落就是串台。
- 口径不一致(一边 CLTC 一边 EPA)不能并排比,抽取阶段就不许合并。

### 用车成本段

`buyguide` 方向新加了「用车成本」段:电费 / 油费、保险、保养、轮胎 —— 买车只看指导价
是不够的,持有成本往往比差价更能决定值不值。该段要求引用事实(缺料就整段跳过,
不让脚本硬写"没有记录"这类查无实据的结论),并且必须带**口径**(按什么价、什么工况算的)。

### 主论点(`Project.thesis`)

一条视频要有一句贯穿全片的判断,不然就是参数流水账。主论点由**生成脚本的同一次 LLM 调用**
产出(不额外多花一次调用),是一句 ≤30 字的判断:

- 结论段必须**原样包含**它,否则 lint 提醒;
- 它是封面的副标题(见"封面"),也是全片的方向锚;
- 门禁 A 可以改,改完存进 `projects.thesis`,lint 按新主论点重判。

### 合规检查(`script_gen.compliance_lint`)

- 品类禁用词 + 方向级附加禁用词 + 广告法绝对化用语
- 引用了不存在的事实 ID
- 品类必需免责声明自动追加
- **禁止贬低竞品**:点名了竞品 / 友商 / 同级,又用了「智商税」「劝退」这类贬义词即拦下;「A 不如 B」这类客观比较不拦
- 用公司事实讲产品参数(只在产品向方向生效)
- **禁止厂商口径当论据**(只在竞品 / 对比 / 横评章节生效):厂商自己做的消费者选择调查
  拿来证明本车比对手强,是替厂商站台。识别「官方表示」「调研显示」「某某说,……」这类归因。
  同一段里的横向比较必须换成可比参数(售价 / 续航 / 加速 / 配置)。
- **黄金三秒**(只在开场段生效):第一句超过 18 字、或出现开场套话即拦下
- **禁止空洞评价**:`vocab.filler_terms` 命中即拦下
- **对比事实不进本车段落**:非对比段引用 `compare_with` 事实即拦下(横评方向豁免)
- 重复检测:同一条事实被多个章节引用、同一个数字在 3 段以上反复出现(提醒级)
- 结论段没回扣主论点(提醒级)

`error` 级问题**不修不放行** —— 门禁 A 确认时会重跑一遍,有问题就拦下
(见"门禁 A 预审")。`warning` 只提醒。

### 大字与旁白不许复读(`explainer.echoes_narration`)

旁白本来就有字幕,大字再把旁白原话抄一遍,同一句话就在画面里出现两次 ——
大字既没加信息,又挡住画面。所以 `highlight` 的大字会做一次复读判定:

- 大字**包含**旁白的某个完整分句(≥4 字)→ 丢掉
- 大字本身就是旁白里的一段(≥6 字)→ 丢掉

丢掉的那一行不补别的:两行都丢光就这一拍退回 `broll`,不留空框。
冷开场(`hook`)不这么判 —— 3 秒里把钩子放大本来就是刻意设计。
旁白在门禁 A 被改过之后,大字会按新旁白**重新核对**一遍。

## 一键发布与数据监控

成片之后接一条**「分发 + 监控」**链路:一条片子一次点击发到 B站 / 抖音 / YouTube /
小红书 / 视频号,并把各平台的作品数据定时抓回来做看板。

页面:**分发台** `/publish`、**数据看板** `/analytics`;项目页成片区有「一键发布」。

### 为什么自己写而不是用现成的

`mcode-tools` 的连接器目录里 176 个工具全部分布在 matrix(多模态)、企查查、
同花顺三类里,**没有任何发布或平台数据类工具**。所以这条链路是本仓库自建的。

### 平台接入(官方 API 优先,Cookie / 浏览器兜底)

每个平台一个 adapter,统一三个方法:`check_account` / `publish` / `fetch_metrics`。
上层(编排 / UI / 看板)只认契约,加平台 = 加一个 adapter。

| 平台 | 首选画幅 | 发布通路 | 数据来源 |
|---|---|---|---|
| B站 | 16:9 | 创作中心 Web 投稿(Cookie:SESSDATA + bili_jct,免资质) | 公开接口 `archive/stat` |
| YouTube | 16:9 | Data API v3 + OAuth2 refresh token | `videos.list(part=statistics)` |
| 抖音 | 9:16 | 开放平台 `create_video`(需 `video.create` 能力) | `video/video_data` |
| 小红书 | 9:16 | 浏览器自动化(创作服务平台) | 后台数据页文字解析 |
| 视频号 | 9:16 | 浏览器自动化(视频号助手) | 助手数据页文字解析 |

- **B站** 的五步投稿链路(preupload → 申请会话 → 分片 PUT → 合片 → 封面 + `add/v3`)
  每一段都做了多路兜底,失败时把平台原始返回带出来,方便对着抓包改。
- **抖音** 单文件 ≤100MB,超了先转一版 720p 再传(平台自己推荐的也是 720p 起)。
- **小红书 / 视频号** 没有开放平台 API,只能驱动已登录的浏览器:分发台点「登录」
  扫码一次,登录态存在 `data/_browser/<平台>.json`。浏览器复用本机 Chrome / Edge,
  只装 `playwright` 这个 Python 包,**不必** `playwright install` 再下一份。

### 竖版(9:16)

抖音 / 小红书 / 视频号是竖屏生态,16:9 发过去会被重排裁切。所以成片之后会自动补一版
`output_vertical.mp4` + `cover_vertical.jpg`。

**竖版不是另一套渲染管线,是同一条跑第二遍。** 叠加层、字幕、封面本来就都吃 `size`
参数,缺的只是"按 1080×1920 再渲一遍":

- 背景走「前景完整缩进画幅 + 同画面模糊铺满」(`explainer._fit_filter`),不硬裁 ——
  16:9 源硬裁成 9:16 会把车头车尾切掉;
- 概念动画只支持 1920×1080,竖版这一拍自动**退回数据卡**(与既有的降级行为一致);
- 字幕字号按**短边**算(横竖都是 60px),一行 15 字放得下。

代价是上下会留一条模糊带 —— 16:9 素材做竖版本来就是妥协,不是原生竖屏。

### 发布是任务,不是一次函数调用

上传 100MB 要几分钟,HTTP 请求不可能等它。所以每次发布写一条 `publications` 记录:

```
pending ──► uploading ──► submitted ──► published
   │            │             │
   └────────────┴─────────────┴──────► failed ──(可重试且未超次数)──► pending
```

后台调度器每轮领几条待办推进,落库一次。好处有三个:

- **幂等**:唯一索引 `(项目, 账号, 画幅)`,同一���片不会发两次;
- **断点续跑**:进程重启后任务还在库里;
- **多平台不回滚**:B站成了、抖音挂了,B站仍是 `published`,抖音单独重试。

执行放在**独立 daemon 线程**里,不和 Web 事件循环抢时间。同一账号的任务严格串行
(单账号高频上传会触发风控),跨账号并行。

文案是自动生成的(`app/publish/metadata.py`,纯函数):标题按平台上限裁且**不切在词中间**,
简介带上品类免责声明与素材来源,标签从主体与事实主题派生。发布前会再跑一遍
`compliance_lint` 的禁用词表 —— 命中就不发,投放被拒等于白忙。

### 监控

每 30 分钟抓一次已发布作品的公开数据,写进 `metric_snapshots`。

| 平台 | 播放 | 点赞 | 评论 | 收藏 | 转发 | 投币 | 弹幕 | 涨粉 |
|---|---|---|---|---|---|---|---|---|
| B站 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| YouTube | ✓ | ✓ | ✓ | — | — | — | — | ✓ |
| 抖音 | ✓ | ✓ | ✓ | — | ✓ | — | — | 有能力才有 |
| 小红书 / 视频号 | 后台页文字解析,字段随页面改版而变 |

**缺失就是 None,不用 0 顶替** —— 0 和"没权限"在看板上完全是两回事,拿 0 顶替会把
"没权限"画成"零播放"。趋势图遇到缺失会**断线**,不连到 0。

完播率、观看时长、观众画像这些深度指标在表里预留了字段,但本期不实现 —— 那些数据
各平台都不在公开接口里给。

### 凭据

- **用户态凭据**(各平台 cookie / OAuth token)→ `data/accounts.json`,由分发台的
  「添加账号」写入。`data/` 与 `cookies/` 已被 `.gitignore` 覆盖。
- **应用级密钥**(抖音 client_key/secret、YouTube client id/secret)→ `.env`。
  理由:应用密钥是开发者资产、不随账号变;用户 token 是账号资产、要按账号管理。
- 凭据**不出现在任何 API 响应里**:对外一律是 `has_credential` + 末 4 位。

## 并行渲染

后台调度器把处于自动态(逐拍渲染 / 转成片 / 合成)的项目排进队列,
由 `PIPELINE_CONCURRENCY` 个 worker 推进:

- **同一项目**同一时刻只有一个写入者 —— 门禁确认、重拍、保存脚本这些
  人工操作与后台推进撞上时,人工操作会收到"该项目正在推进中"(HTTP 409),
  不会两边一起改同一个文件;
- **不同项目**可以并行渲染。渲完一批拍若仍在渲染态,会重新入队(排到
  队尾),所以一个长项目不会把其它项目饿死。

```bash
# .env
PIPELINE_CONCURRENCY=1   # 同时推进几个项目
```

**内存是硬约束**:峰值 Chrome 进程数 ≈ `PIPELINE_CONCURRENCY` ×
`MOTION_WORKERS`(每个约 256MB),磁盘也会被成倍放大(每渲一拍拍就多几十
MB)。机器内存吃紧就保持 1,确认有余量再往上调。`data/` 的体积可以在
`/api/health` 的 `disk` 字段看到,超阈值会在首页提示。

服务被收走时(托管后台任务有 1 小时上限),渲染会在**拍与拍之间**收手:
手头这一拍做完就停,剩下的拍留到下次,重启后从断点接着跑 —— 不会留下
半截 mp4。

- **方向**(`themes`):一条视频只讲一个方向,当前是 `buyguide`(单车选购深讲)。每个方向声明自己的事实来源、

## 两种接口后端:mcode 与 direct

所有外部能力都经过 `providers/cli.call(工具名, 参数)`,`CONNECTOR_BACKEND` 决定它落到哪:

- **`mcode`**:`mcode-tools` CLI,登录由 MiniMax Code 托管,离开 MiniMax Code 就调不通。
- **`direct`**:`providers/direct.py` 用 M Plan 订阅 Key 直连开放平台,返回与 Connector 相同的形状。

| 能力 | direct 实现 | 备注 |
|---|---|---|
| 配音 / BGM / 生图 / 音色 | `/v1/t2a_v2`、`/v1/music_generation`、`/v1/image_generation`、`/v1/get_voice` | 模型由 `TTS_MODEL` / `MUSIC_MODEL` / `IMAGE_MODEL` 指定 |
| 图片理解 | `/v1/coding_plan/vlm` | 素材池打标签用;本地图转 data URI |
| 图片检索 | Bing 图片 | 开放平台没有图片检索接口 |
| 事实:新闻检索 | `/v1/coding_plan/search` | `source_tool` 记为 `minimax.web_search` |
| 事实:同花顺行情财报 / 企查查 | **不支持** | 该来源记失败,其余照常 |

`.env` 填 `MINIMAX_PLAN_KEY`、`CONNECTOR_BACKEND` 留空时:有订阅 Key 且找不到 `mcode-tools` 就走 direct。
自检:`python -m tests.verify_direct`。

⚠️ `/v1/coding_plan/vlm` 与 `/v1/coding_plan/search` 是套餐接口,M Plan 2026-10-31 到期后可能直接不可用。

## 成本说明

界面上的金额一律是**等效用量**(`costs.py`,MiniMax 国际站标价折算;BGM、LLM、VLM 单价是粗估),仅用于
项目级节流阈值与套餐到期后的参考,**不是账单**。

- 单条片子:`estimate_explainer` = TTS(约 5.8 字 / 秒)+ BGM(命中曲库为 0)+ 3 次 LLM,留 1.2 倍给门禁 A 改稿重确认。
- 素材池:`estimate_library` = 视觉调用次数 × 单价 + 每 12 张一次 LLM,每台车一次性,项目页单独显示。

### 配额是真的会拦的

每个项目有一个等效用量上限(`quota_budget`)。花钱的阶段在**调用之前**先按预估
预留额度(`costs.project_spend`),调用完再按实际结算:

- 预留时若"已花费 + 在途预留 + 本次预留"超过上限,**这次调用不会发生** ——
  事实抽取、脚本生成、逐拍版式、门禁 A 的 TTS 合成都在闸门后面;
- 素材池打标签(视觉调用)也算进项目的额度,额度不够就**不建池**(背景素材
  重复一些不影响出片,不值得为它把整条片子停掉);
- 超限时项目转入 `PAUSED_BUDGET`,**不会**被标成失败 —— 它没坏,只是没钱了。
  暂停前的状态记在 `projects.resume_state`;
- 在项目页填一个新的上限提交,项目会回到暂停前的那个状态接着干
  (`PATCH /api/projects/{id}/budget`)。

### 前端工程化工具链

前端代码本身是**零依赖、零构建**的原生 ES Module(浏览器直接跑,不打包不转译)。
根目录的 npm 工具链只用来检查,不会进产物:

```bash
npm install                # 装 vitest / eslint / prettier / typescript
npm run check              # 一条命令跑完:lint + 类型检查 + 单测
npm run lint               # eslint(app/web/static/js)
npm run typecheck          # tsc --noEmit(app/web/jsconfig.json,checkJs)
npm test                   # vitest:75 条前端单测(tests/web/)
npm run format             # prettier 统一格式
```

- **单测**用 vitest + jsdom,测的是容易悄悄坏掉的地方:`h()` 造元素、
  `withLoading()` 的防重复提交、`relTime()` 的时间档位、`api` 的错误处理
  (422 的 `detail` 是数组时拼成一句话)、toast 的堆叠上限、弹窗的确认/取消、
  脚本"有没有未保存的修改"(判断错会静默丢用户的编辑)、
  视频单拍 404 时退回草稿(成片合成后单拍会被清掉)、三类筛选判断。
  为了能测,这些判断从页面脚本里抽到了 `app/web/static/js/ui/{filters,dirty,media}.js`。
- **类型检查**用 JSDoc + `checkJs`,不加 TS 也不加构建步骤。它已经抓出过真 bug:
  `project.js` 的 `act()` 忘了 `return`,导致"门禁 A 被 lint 拦下 → 仍然继续"
  的二次确认永远不触发,用户被卡死 —— 现在类型检查会直接报出来。
- 不接 CI,检查都在本机跑:后端 `python -m pytest tests -q`、前端 `npm run check`。

> 并行跑两个 pytest 会互相污染真实的 `data/` 目录,预算那类用共享状态的测试会假失败。
> 要并行请给每个进程单独的 `DATA_DIR`。

### 概念动画的渲染回归

改完模版或骨架后跑一下,画面变了会报出来:

```bash
python scripts/motion_regress.py                  # 渲染 27 个模版 × 2 个时刻,和基线逐像素比
python scripts/motion_regress.py --save-png out/  # 顺便把 PNG 存下来供肉眼比对
python scripts/motion_regress.py --update         # 确认是想要的改动后重建基线
```

基线在 `motion/regress/baseline.json`,存的是**原始像素的哈希**(不是 PNG 文件 ——
容器元数据会变,像素不会)。实测精度:改一个被完全遮住的底色、或者改一个被 JS 内联
样式覆盖的 CSS 字号,它都判"画面没变";改真正生效的字号,它立刻报出哪一帧变了。

**只能在装了 HyperFrames + Chrome + 中文字体的机器上跑**,别塞进 CI:HyperFrames 按
页面上出现的字符裁内嵌字体子集,字体集合不一样,同样的模版渲出来的像素也不一样。

## 已知限制

- **`mcode-tools` 认证**:只能在 MiniMax Code 里用,别处请用 direct 后端。
- **direct 后端少两样**:同花顺 / 企查查的行情、财报、工商数据只能经 MiniMax Code。
- **素材依赖本机网络**:B站 / 汽车之家国内直连;YouTube、TikTok 需要 `YTDLP_PROXY`;抖音多半需要 `YTDLP_COOKIES`。
  新车、小众车型的官方素材少,池子薄时背景会重复。
- **`app/llm/minimax.py` 未经验证**:配置了 `MINIMAX_API_KEY` 后 `orchestrator._llm()` 会优先用它。
- **多车横评**(多个主体、每车一池)尚未实现。
- **平台接口没有正式文档**:B站创作中心投稿、抖音/小红书/视频号的后台页面都是抓包逆向来的,
  平台改版就要跟进。解析失败会明确报错并降级,不会静默假装成功。
- **抖音/小红书/视频号没有稳定的公开 API**:抖音开放平台要企业资质与能力审核,
  小红书与视频号干脆没有发布 API,只能驱动浏览器。后台页面的选择器随改版而变,
  属于长期维护成本,不是一次性工作。
- **竖版是妥协**:16:9 实拍做 9:16 必然留模糊带,不是原生竖屏。
