# 车评人视角:为什么这条产线的片子"不吸引人",以及怎么改

> 分析对象:`data/projects/p_3de7193d9669/output.mp4`(2026-10-21 渲染,3:11 / 30 拍 / 小米 YU7 选购向)
> 素材池:`data/library/小米yu7/library.json`(260 条,60 官图 + 200 视频段)
> 脚本:`data/projects/p_3de7193d9669/script.json`(今日产出,30 段)
> 视角:一个做了八年汽车视频的评车人,坐在观众的位置上看这条片子。

---

## 0. 一句话结论

**你的产线把"可信"做到了 A 级(数字可追溯、语境合规、不吹牛),但车评视频的吸引力来自另外三件事——立场、体验、争论——目前一条都没有。**

现在的成片在专业车评人眼里是一份**会动的说明书**:信息密度够、证据密度高、没有一处硬伤,但观众看完记不住任何一句,也没有理由点下一期。

更要命的是第一帧:开场那个"别急着订车"的钩子,配的是**一台低趴双门轿跑**,右上角还挂着第三方账号 `Soda' bilibili` 的台标。车评视频的前三秒只干一件事——**确认"这就是我要看的那台车"**。这一帧就把这件事办砸了。

## 1. 证据:三处硬伤

### 1.1 开场第一帧:配的不是这台车,还带别人的台标

抽帧(成片 t=2s)实测:

| 项 | 实测 |
|---|---|
| 背景车型 | 低趴双门轿跑,车身轮廓与 YU7(中大型 coupe SUV)完全不同 —— **不是这台车** |
| 角标 | 右上 `Soda' bilibili`,第三方博主的账号水印 |
| 画面内容 | 钩子大字压在车身上,主体被标题吃掉一半 |

素材池体检(200 段视频,共 1127 秒):

| 分类 | 段数 | 秒数 | 占比(秒) |
|---|---|---|---|
| 视频总��� | 200 | 1127 | 100% |
| `problem` 空(干净) | 48 | 102 | 9% |
| **干净 且 确认是这台车** | **3** | **9** | **0.8%** |
| 干净 且 官方来源 | 16 | 70 | 6% |
| 干净 且 官方 且 确认是这台车 | 1 | 3.3 | 0.3% |
| `target=unknown`(车型没认出来) | 146 | 703 | **62%** |
| `text_overlay`(带角标水印,非官方) | 8 | 83 | 7% |
| `subtitle`(有烧录字幕,可裁) | 80 | 393 | 35% |
| `poster`(海报/展台) | 15 | 331 | 29% |
| 官图(静图) | 60 张 | — | — |

结论:**池子有 62% 的时间长度"不知道是不是这台车",只有 0.8% 是"干净且确认是这台车"。**
`_fill_tier` 只把"非官方 + target≠yes"往后排(+10 档),不禁止;`HARD_FILTER_MIN_SECONDS=60` 又让"干净池不足 60 秒时"放弃硬过滤。于是带台标的第三方片段照样能进第一帧 —— 而 VLM 把 Soda 那条源里 25 段判成了"干净",`text_overlay` 只标出 8 段。**"禁用第三方台标"这条 P0 实际上没生效。**

### 1.2 脚本:是参数流,不是判断流

今日产出的 30 段原文摘录:

```
[5]  外观设计 :: 这车第一眼就是大,车长4999毫米。
[6]  外观设计 :: 宽1996、轴距3000毫米,比例压得很低趴。
[8]  外观设计 :: 但要提醒一句:系数低不等于总风阻小,还得乘迎风面积,大车高速电耗照样受车身体量影响。
[12] 内饰空间 :: 25扬声器全系标配,家里有娃的还能用晕车舒缓模式,晕车发生率降低51%。
[29] 结论建议 :: 总结:适合看重智能配置、想要大空间纯电SUV的家庭用户;不适合只认燃油补能、或者预算卡得很死的人。
```

车评人和你的差别不在"信息对不对",在**每句话后面跟不跟一个"所以对你意味着什么"**:
- 「宽1996、轴距3000毫米」→ 车评人会说「车宽快到两米,老小区地库那条拐弯,得先确认你敢不敢一把打过去」。
- 「晕车发生率降低51%」→ 车评人会说「有娃家庭这条比音响值钱」。

你的 `script_rules` 里写着「不许自己推测缺点(空间、做工、屏幕反光、异响之类),没有依据就不说」——这条对合规是好事,但它同时**制度性地取消了"体感"这一层**。事实层只有 `product/company/industry` 三种 scope,来源全是新闻检索;试驾、评测、车主口碑这类**体验类事实根本进不来**。所以这条产线在结构上**只会说参数,不会说感受**。

### 1.3 画面:三处观感硬伤

抽帧实测:

| 拍 | 实测问题 |
|---|---|
| `stat`(大数字) | **整屏纯黑**,只有一行数字和一行小字。3:11 的片子里这样的空镜不少,像 PPT 翻页,不像视频 |
| `panel`(参数面板) | 官图被压成半屏,上下留黑边,车头被切;面板里**口径标签(`标准版·2026款｜官方`)比数值本身还抢眼**,行名/值/口径三层没有主次,像后台表格 |
| `highlight`(大字) | 画面是一张糊掉的喇叭特写,大字直接压在图上,没有安全区 |
| 章节条 | 7 个章节挤在一条 45px 高的条里,手机端几乎不可读 |

## 2. 车评人的吸引力公式 vs 你的产线

一个有人追更的车评号,每期必须回答三个问题:

| 车评要素 | 观众心里的话 | 你的产线现状 | 差距 |
|---|---|---|---|
| **立场** | "他站哪边?我信不信?" | `thesis` 机制有了(≤30 字判断),但**全片只有结论段用得上它**,中间 25 段是中立解说 | 观众感觉"这人在念参数",不是"这人在给建议" |
| **体验** | "开/坐上去什么感觉?" | 无体验类事实源;只有算术体感(`每分钟补 27 公里`) | 最有感染力的一层整体缺失 |
| **决策** | "我该买吗?掏多少?" | 版本选择段有推荐,但没给**门槛**("预算卡死""没有家充桩"才是真实决策变量) | 有结论,没有可执行的决策条件 |
| **争论** | "我不同意!" | 无 | 没有可吵的锚点 → 评论区必冷 |
| **信任** | "这数字是真的吗?" | **A级**:fact_refs + 逐行核对 + 合规 lint | 这是你的护城河,别丢 |

一句话:**信任你已经赢了,但信任不产生点击,立场和体验才产生点击。**

## 3. 改造清单(按 影响力 ÷ 改动成本 排序)

### P0 · 先止血(不做这三条,后面全白改)

**P0-1 第一帧必须确认"是这台车"**
把 `target != yes` 从"降权"改成"**不进背景**",官方来源提权到最前;VLM 对"同品牌不同车系"判得更保守(小米 SU7 的片段不能给 YU7 用)。
落点:`app/pipeline/library.py` `_fill_tier` / `_fill_tier_base`;`app/pipeline/vision_verdict.py`。
验收:池子里"干净且确认是这台车"从 3 段 / 9 秒 → **≥ 40 段 / ≥ 120 秒**;不足就少用视频、官图兜底,而不是拿不确定的片段顶。

**P0-2 第三方台标在第一帧消失**
`text_overlay` 判定靠 VLM 太脆(Soda 源 25 段被判成干净)。加**几何兜底**:检测/裁掉画面角标带(右上右下各 12%),或干脆把非官方 `text_overlay` 段永久拉到最后档并标记;同时给 `problem` 判定补一条"角落有半透明小字/固定图形"的样本。
落点:`library.py` `_hard_bad` / `_dirt`;`library.py` 铺背景时的裁剪参数。
验收:成片任意一帧右上/右下角不出现第三方账号名或图形。

**P0-3 每个大数字必须挂一个参照系**
车评的数字永远是相对的。「23.35 万」单独看没有意义;「23.35 万,是 25–30 万纯电中大型 SUV 里最低的那一档」才有决策价值。
落点:`app/categories/profiles/auto_long.yaml` → `themes.buyguide.fact_sources` 增加同级价位带采集;`script_gen.py` 增加规则:每个 `stat` 拍必须有 `compare` 事实支撑,否则降级为面板。
验收:全片每个大数字都能一句话说出"比谁高/低"。

---

### P1 · 内容层(最能拉开差距,也是别人抄不走的)

**P1-4 给每段加"所以呢"**
车评语言的核心动作。规则化写法:**参数 → 含义 → 对谁有影响**。
落点:`script_gen.py` `SYSTEM` 第 2 条 + `auto_long.yaml` `script_rules`;新增一条 lint:某段只有参数没有"含义句"→ warning。
示例改法:
- 改前:「15 分钟补能 405 公里」
- 改后:「15 分钟补 405 公里 —— 你吃个饭的时间,够它从上海开到南京再回来」

**P1-5 开一条"体验事实"通道(内容天花板)**
现在事实只有新闻检索,试驾/评测/车主口碑进不来。加一类来源(懂车帝评测、汽车之家评测稿、专业自媒体长测),抽取时**保留媒体评价类 claim**,标 `source_kind=media` / `confidence=medium`,脚本里允许转述(「媒体普遍提到…」),但仍禁止自己臆断优点缺点。
落点:`app/pipeline/intake.py` `EXTRACT_SYSTEM`(第 160 行起)加一条抽取规则 + `auto_long.yaml` `fact_sources` 加来源;`Fact.scope` 可考虑新增 `experience`。
注意:这是把"不许推测"改成"只许转述有出处的体验",合规底线不变。

**P1-6 结论段升级成"可截图的决策卡"**
现在的结论是"适合谁 / 不适合谁"(对,但没法转发)。改成一张有结构的卡:**3 个关键数字 + 2 类人 + 1 个时间点**。
落点:`auto_long.yaml` `sections.结论建议` 的 `beat` 与 `layouts`(加 `card`);`explainer.py` 的卡片类型。
示例:「23.35 万 / 835 km / 15 min 405 km · 有家充桩选标准版 · 常跑高速选长续航版 · 等官降 2 万再下手」

**P1-7 钩子从"选题式"升级到"立场式"**
现在:「别急着订车,先搞清楚 YU7 买哪版」——**正确但中性**,这是选题说明,不是观点。
车评钩子是**立场**:「23.35 万买到的不是配置,是小米敢不敢赌电池方案的那份底气。」/「买 YU7 的人,一半在买屏幕,一半在买 15 分钟。」(立场 + 悬念 + 可争论)
落点:`script_gen.py` `SYSTEM` 第 8 条加正反示例对照;`script_gen.py` `hook_lint` 增加"是否含取舍/立场"的软判据。

**P1-8 给全片一条"信息曲线"**
现在 30 段是平的:参数 → 参数 → 原理 → 参数。专业车评的节奏是**钩子 → 建立可信 → 逐层加码 → 反方 → 落地**。
给每章加一个强度标签(`intensity`),由 `concept` / `stat` / `highlight` 承载高潮拍,让"最强的一击"落在观众还没走的时候。
落点:`auto_long.yaml` `sections` 每段加 `intensity: 1-3`;`app/pipeline/explainer.py` 版式选择读它。

**P1-9 让"取舍"成为一等公民**
`principles` 库里每条都写了 `tradeoff`(代价/边界),但脚本只是把它当补充说明讲。车评必须把取舍**提到台面上当判断**:「这个配置对你意味着什么,代价是什么,值不值」。
落点:`script_gen.py` 要求每条被引用的 `k_` 原理,**其 tradeoff 必须在本段出现**;`auto_long.yaml` `depth_sections` 已限定三电/智能两段,可扩到全部技术段。

### P2 · 画面与分发

**P2-10 画面三处修**
- `stat` 拍别用纯黑底:车在暗处 + 大数字 + 一点点光,而不是空屏。
- `panel` 信息层级重排:**数值最大 → 行名次之 → 口径最小最灰**(现在是口径标签最抢眼)。
- `highlight` 拍的安全区:大字不许压在主体上,缩到画左 1/3 或加渐变底。
- 章节条从 7 个缩到 4 个(横屏),字提到 34px 以上(README 提过 P1,横屏这条建议同步落地)。
落点:`app/pipeline/explainer.py`(stat 背景处理)、`app/pipeline/hud.py` / `cards.py` / `overlays.py`(层级)、`app/pipeline/overlays.py`(章节条)。

**P2-11 标题公式换成"车评标题"**
现在是参数解说号命名法。换成 `[价格带] + [人群/场景] + [反直觉结论]`:
- 现在:「小米YU7 值不值得买 该怎么选」
- 改后:「23.35 万的 YU7,买的是屏幕还是电池?」
落点:`app/publish/metadata.py` 标题生成;`script_gen.py` `title` 规则。

**P2-12 竖屏当"钩子段"做,不是整片竖版**
竖屏链路今天已经跑通(`durations_portrait: [60,90,120,180]`),但现在是横屏 blocks 砍短。抖音/小红书的流量逻辑是**一条片只讲一个反直觉结论**(30–60 秒),横屏长片是留存资产 —— 两者应该用不同的段落块。
落点:`app/categories/profiles/auto_long.yaml` 给竖屏单独一套 `blocks`(只保留 开场/一个爆点段/结论),`app/pipeline/orchestrator.py` 按画幅选块。

**P2-13 结尾提问改成"选项式"**
「你在纠结哪款?」太泛。改成逼选边:「A 标准版还是 B GT?评论区给我,下期我开这两台实测对比。」
落点:`script_gen.py` `ending_lint` + `auto_long.yaml` `script_rules`。
落点上的落点:结尾提问与下期预告**要绑定一个真实可做的下期**(你的 `roundup` 主题已经具备做横评的能力),别留空头预告。

## 4. 如果只做三件事

1. **P0-1 + P0-2**:第一帧换成"确认是这台车、没有任何第三方台标"的画面。
   —— 这是唯一一件"不改内容、不改文案"却能立刻提升观感的事。观众在 3 秒内决定划不划走。
2. **P1-4 + P1-7**:每段加"所以呢",钩子改成立场句。
   —— 把"参数流"改成"判断流",边际成本几乎为零(只改提示词 + 一条 lint),但内容观感质变。
3. **P1-3 + P1-6**:每个大数字挂参照系,结论变成可截图的决策卡。
   —— 提高"收藏/转发/评论区引用"这三项,这是长视频最实在的二次传播来源。

## 5. 一个残酷但有用的判断

**如果不引入"立场 + 体验",这条产线做到极致也只是最好的参数解说号。**

参数解说号的天花板是"**被当成工具查**"(用户搜"YU7 续航多少"→ 你的片被当工具链的一环),不是"被当成人追"。而且工具属性最容易被下一个模型抹平 —— 参数是公开信息,谁都能查。

真正抄不走的是**一个持续表达判断的人格**。在 AI 产线里,人格不可能来自音色(换 TTS 音色等于换个人),只能来自**内容的立场一致性**:每期的判断都在同一条线上,观众才认得出"这是同一个人说的"。`thesis` 机制已经有雏形,把它从"结尾出现一次的句子"升级成"全片每一段都在服务的立场",人格感才会出现。

所以这份清单的排序逻辑不是"什么改起来快",而是:**先止血(让人愿意看完),再加判断(让人愿意追),最后做包装(让人愿意点)。**
