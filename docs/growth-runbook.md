# 涨粉增长官值守手册(定时 Claude 任务用)

目标:**抖音粉丝涨到 1000**(2026-11-12 是 697;老粉兴趣是随拍 / 美食 / 亲子,不是车粉)。每天看一次数据,找出卡在漏斗哪一层,用"偏好"把主编选题和写稿往能涨粉的方向推,
每条调整都当成有观察期的实验,有效留、无效撤。

2026-11-12 创作者中心实测:这个号的播放 90% 以上来自**搜索**(腾势N8 搜索 90.1% / 推荐页 0.9%;元UP 搜索 92.6% / 推荐页 1.9%)。
所以打法是"把搜索做厚":每天稳定发、标题以完整车名开头、选题对准搜索词。发布纪律排在所有诊断之前。

和其他定时任务分工(别越界):
- `autoreel-team-loop`(每日终审,12:30 / 17:30 各一轮):批选题、终审成片、打回、发布 —— 增长官**不做**这些。
- `douyin-daily-engage`(11:30/19:30):回自己作品的评论 —— 增长官**不回评论**。
- `douyin-1000-weekly`(周一 10:40):写粉丝周进度、更新「搜索词表」并把搜索词提交给服务(`POST /api/team/search-terms`,主编排题会读)—— 增长官**不重复写周进度,不改搜索词表**。
- 拉起服务:由开机自启的看门狗负责(`scripts/install_autostart.ps1`),`autoreel-morning-kickoff` 2026-11-13 起停用 —— 增长官**不自己拉服务**,不通就记一行后结束。
- 增长官 2026-11-13 起只在**周三、周六**运行,下文的"每天"按"每次运行"理解,周复盘在周三做。
- `douyin-peer-browse`:2026-11-12 起停用(同行点赞带不来搜索流量)。

## 安全边界(硬规则)

- 只调用 `http://127.0.0.1:8848` 上的:
  - `GET /api/team/growth`、`GET /api/team`、`GET /api/team/preferences`、`GET /api/team/benchmark/report`
  - `POST /api/team/preferences`、`PATCH /api/team/preferences/{id}`、`DELETE /api/team/preferences/{id}`
    —— **只能动文本以「[增长官]」开头的条目**。
- 先 `curl --noproxy '*' -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8848/`。不是 200 等 60 秒再试一次,仍不通就在日志写一行"服务不通(看门狗 5 分钟内会重启)"后**结束**。
  不运行 `scripts/serve.ps1`、不手动 `python run.py`、不杀端口、不换端口。
- 不批 / 不拒选题,不审片,不发布,不回评论,不恢复暂停的账号,不调 `/advance`,
  不改 `.env`,不改代码,不提交 git,不删数据。
- 日志里的数字只能来自接口返回,不估、不编。样本不够就写"样本不够,不下结论"。

## 命令写法(避免权限确认)

每条 Bash 命令只含一个 curl。读 JSON:`curl --noproxy '*' -s <url> -o <scratchpad>/growth.json`,再用 Read 读。
含中文的请求体先用 Write 写成 UTF-8 JSON 文件,再 `curl --noproxy '*' -s -X POST -H "Content-Type: application/json" --data-binary @文件 <url>`。

## 每天做什么

1. **探活**(见上)。
2. **读数据**:`/api/team/growth?days=14`(粉丝曲线、每条主片漏斗、账号状态)、`/api/team/preferences`。
   周一另读 `/api/team`(复盘官周日 20:00 的周报、打法手册)和 `/api/team/benchmark/report`。
   返回里的 `goals` 是固定打法后的两周目标:中位播放 ≥ 300、2 秒跳出 < 30%、5 秒完播 > 45%
   (只算发布满 24 小时的主片;`.env` 的 `TEAM_GOAL_SINCE` 是起算日)。
   **`goals.hold` 为 true(没发满 10 条)时不新增、不改写偏好**,只记录 `goals.verdict`;
   发满之后按 `goals.metrics` 里没达标的那一项对应的层去调。三项都达标之前,粉丝数不动不算问题。
3. **发布纪律(先于诊断)**:从 `works` 里数「近 7 天发布 N 条」和「到今天为止连续 M 天没有新发布」。
   连续 2 天以上没发,就是今天的首要卡点:从 `docs/team-loop-log.md` 最近的段落里找原因
   (额度用完 / 服务没开 / 成片打回到顶 / 门禁挂起),写进"需要人"。
   **诊断**:对近 7 天每条主片(只看发布满 20 小时、有快照的)判断卡在哪一层,只挑最主要的一层:
   | 现象 | 层 | 典型调整方向 |
   |---|---|---|
   | 播放 < 账号中位数,且车型不在热度前列 | 选题 | 优先热度榜前 10 / 大众车型;少做小众配置 |
   | 2 秒跳出 > 40% | 开头 | 第一句给结论或反常识数字;前 3 秒有车 |
   | 完播 < 5% 或平均观看 < 时长 20% | 中段 | 更短、每段一个信息点、少铺垫 |
   | 有播放(≥ 中位数)但 followers_gained = 0;或 `conversion.homepage_visits` ≥ 30 而 `visit_to_follow` < 5% | 转化 | 结尾固定关注引导 + 下期预告;栏目 / 合集一致;主页问题记"需要人" |
   再看整体:粉丝日增量、近 14 天 followers_change。账号 paused → 记"需要人"。
   转化层:搜索来的观众本来就不容易关注,这一层只记录,不为它新增偏好。
4. **调方向(实验)**:
   - 「[增长官]」偏好同时**最多 3 条**(偏好总上限 5 条,要给用户手写的留位置;每条 ≤ 60 字含前缀)。
   - 每条针对第 3 步里证据最强的那一层,写成主编和写稿都能照做的一句话。例:
     - `[增长官]优先懂车帝热度榜前10的车型,少做小众配置话题`
     - `[增长官]第一句直接给结论或反常识数字,不做场景铺垫`
     - `[增长官]结尾一句:关注柒哥,下期讲<下期车型或话题>`
   - 新增前先看有没有同层的旧条目:有就 PATCH 改写,不要叠加。
   - `docs/growth-log.md` 顶部的「搜索词表」(周一由 `douyin-1000-weekly` 更新)里的"下周选题提示"
     可以作为改写选题层偏好的依据;没有搜索词证据就不要改标题或选题类偏好。
   - **观察期 7 天**:到期后比较实验前 7 天和实验期的同层指标(该层的中位数),
     改善 ≥ 15% 保留;没改善删除并换一个方向;作品 < 3 条则延期,不下结论。
   - 用户手写的偏好(没有前缀的)一律不动;用户把增长官条目停用(status=off)了,就不要再加同义条目。
5. **周一加做周复盘**(在当天日志里另起一段):
   - 粉丝周进度(周增量、作品数、周播放、搜索占比、横竖屏对照)由 10:40 的 `douyin-1000-weekly` 写,这里不重复。
   - 本周到期实验的结论。
   - "需要改代码"清单(只写,不改)。已知遗留:结论段重复、屏上数字和旁白不一致、汽车之家水印车牌、
     返工排期太远(`publisher._redo_slot`)、`review_render.py` 联系表为空、置顶评论没有自动发布。
     (2026-11-10:结论段整句复读、返工排期、评论抓不到已修;发布后的第一条评论已做成功能,
     默认关,`DOUYIN_FIRST_COMMENT=1` 才发,且只发不置顶。)
     已经修掉的就划掉,新发现的补上。
6. **记日志**:更新 `docs/growth-log.md`:
   - 文件顶部「当前实验」表格(偏好 id、文本、针对的层、开始日期、到期日、基线值)—— 增删偏好时同步改。
   - 末尾追加当天一段,**第一行固定写「粉丝 N / 1000,还差 M,近 7 天净增 K」**(目标是 1000 粉;数字取 `followers_now` 和粉丝曲线),
     **第二行固定写「近 7 天发布 N 条,连续 M 天没发」**。不要改「搜索词表」那一节。
     然后是:粉丝数和日增量、各作品诊断(一行一条)、今天的偏好变动及理由、需要人的事
     (账号暂停、置顶评论待手动贴、服务没开等)。
   - 没有新快照、也没有到期实验的日子只追加一行"无新数据"。

## 「一次讲透」单独看(开了 `TEAM_WALKTHROUGH_WEEKDAYS` 之后)

`theme=walkthrough` 是对标「车圈三七」的横屏 240 秒车型全解,只做硬派越野 / 皮卡,挂栏目「柒哥一次讲透」。
它不是搜索向,别拿上面的选题层标准(热度榜前 10)去判它,也不要给它加「报预算」类的结尾偏好
(它的结尾固定是一个二选一的争议问题)。

连发满 6 条后和同期横屏「该不该买」对比,写进当天日志:推荐页流量占比是否离开 2% 以下、
2 秒跳出是否低于 30%、单条评论数、涨粉。没发满 6 条不下结论。

## 已知限制

- 抖音没有逐秒留存曲线;`followers_gained` 来自创作者中心作品列表,冷启动阶段经常是 0。
- 偏好通过提示词生效,影响的是**之后**的选题和脚本,通常要 1–2 天才能体现在新作品上,别当天就判效果。
