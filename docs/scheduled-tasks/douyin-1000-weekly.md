你在替用户记录抖音号「柒哥&车」到 1000 粉的周进度。项目是 AutoReel-AI(F:\code\aimovice)。回复和日志一律用中文。只做一轮,不循环、不安排下一次唤醒。

【背景】2026-11-12 粉丝 697。约束:只靠现有流水线,不出镜、不投流,不急。老粉兴趣是随拍 / 美食 / 亲子,不是车粉。2026-11-12 创作者中心实测:播放 90% 以上来自搜索(腾势N8 搜索 90.1%、推荐页 0.9%;元UP 搜索 92.6%、推荐页 1.9%),所以打法是"把搜索做厚":每天稳定发、标题以车名开头并对准搜索词。2026-11-13 起做两周横竖屏对照(周一三五横屏「车名,到底该不该买?」,其余竖屏 60 秒)。
**2026-11-17 起改成两条线**:主线「原理拆解」(theme=mechanism,栏目「柒哥拆给你看」,竖屏 3–5 分钟,每周 4 条,标题是「车名,问题句?」),目的是进推荐页、换关注;搜索向(该不该买 / 对比)降为辅线,每周 3 条。原理拆解发满 8 条(只算发布满 72 小时的)后要给结论,通过线:推荐页流量占比中位 ≥ 30%、播放中位 ≥ 500、5 秒完播 ≥ 50%、条均涨粉 ≥ 3。

【先读】F:\code\aimovice\CLAUDE.md 的"服务器与调度器"一节;F:\code\aimovice\docs\growth-log.md 最近两周的内容(找上一篇周报里的粉丝数,以及顶部的「搜索词表」)。

【第 0 步:探测一次服务】
`curl --noproxy '*' -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8848/`。不是 200:等 60 秒再试一次。仍不通就在日志写"服务不通(开机自启的看门狗 5 分钟内会重启,见 data/logs/watchdog.log)"。**不要自己启动服务**,不要运行 ensure_server.ps1 / serve.ps1 / python run.py,不要杀端口,不要换端口。服务不通时本地数据那部分和第 3 步的写入跳过,继续做创作者中心那部分,周报里写"服务不通"。

【第 1 步:本地看板】
`curl --noproxy '*' -s "http://127.0.0.1:8848/api/team/growth?days=14" -o <你的 scratchpad>/growth.json`,再用 Read 读。每条 Bash 命令只放一个 curl。要用的字段:followers(粉丝曲线)、followers_now、totals、conversion(主页访问 → 关注)、goals(metrics / verdict / hold / works;只含搜索向)、goals_by_theme.mechanism(原理拆解自己的一套目标,结构同 goals)、works(每条主片,含 theme 片型、aspect 横竖屏)、accounts(是否暂停)。
再读 F:\code\aimovice\docs\team-loop-log.md 里本周的段落,数出:本周哪几天没有发布成功、原因是什么(额度用完 / 服务没开 / 成片打回到顶 / 其他)。

【第 2 步:创作者中心(只读)】
用 Claude in Chrome(先用一次 ToolSearch 加载 mcp__claude-in-chrome__ 的工具)新开标签页。
a) 打开 https://creator.douyin.com/creator-micro/data-center/operation ,读近 7 天:总粉丝、净增粉丝、吸粉 / 脱粉、播放量、2 秒跳出率、5 秒完播率、完播率,以及粉丝画像里的兴趣前 6(重点看"汽车"有没有出现、排第几)。
b) 打开 https://creator.douyin.com/creator-micro/data-center/content ,点「投稿列表」,读每条作品的:审核状态(通过 / 私密)、播放量、主页访问量、粉丝增量。数出公开作品数和私密作品数。
c) 对近 14 天内发布、且发布满 48 小时、状态为"通过"的每条作品(最多 8 条;原理拆解片优先,一条都不要漏):点该行的「分析详情」(会开新标签页)→ 点「流量分析」标签 → 读「流量来源」里搜索、推荐页、个人主页的占比,和「搜索关键词」前 6 个词及占比。读完关掉这个标签页。只点「分析详情」和页面里的标签,不要点作品封面或标题(会跳去播放页)。
只读:不点编辑、删除、置顶、发布、设置权限类按钮,不改任何设置。要求登录就写"登录态失效,需要人",不输入任何账号信息。Chrome 扩展连不上:重试一次,仍不行就写"扩展未连接,创作者中心部分跳过"。结束后关闭自己打开的所有标签页。

【第 3 步:更新搜索词表】
docs/growth-log.md 顶部「当前实验」下面有一节「## 搜索词表」。用第 2 步 c 读到的数据整节重写(保留表头):每条作品一行,列为 作品(车型)、片型(原理拆解 / 搜索向,按 works 里的 theme 对上)、画幅、发布日、播放、搜索占比、推荐页占比、前 3 个搜索词。表后写两行:
- 「本周带来播放最多的搜索词型」:归纳成词型(如「车名」「A和B对比」「车名+落地价」「车名+能买吗」),数字用表里的。
- 「下周选题提示」:最多 3 条,只能从搜索词里推出来(例:"元UP 的搜索里出现了和长安启源Q05 的对比,可做这两台的对比")。
读不到的作品写"读不到",不要编。
**再把搜索词写进服务**(主编下次排题会读):把第 2 步 c 读到的每个搜索词整理成一条,Write 成 UTF-8 文件 <你的 scratchpad>/terms.json:
`{"terms":[{"term":"元UP 落地价","views":120,"title":"该作品标题"}]}`
views = 该作品播放量 × 搜索占比 × 该词占比,取整;算不出来的词不写。只写页面上读到的词,不补、不改写。然后
`curl --noproxy '*' -s -X POST http://127.0.0.1:8848/api/team/search-terms -H "Content-Type: application/json" --data-binary @<你的 scratchpad>/terms.json`
返回 404 说明服务还是旧代码:周报"需要人的事"里写"重启 8848 让搜索词接口生效",不重试。

【第 4 步:写周报】
在 docs/growth-log.md 末尾追加一段,标题「## 周进度 YYYY-MM-DD」,内容:
1. 第一行:「粉丝 N / 1000,还差 M,本周净增 K」。
2. 按近 2 周的平均周增速估算还要几周;周增速 ≤ 0 就写"按当前速度到不了",不要硬算。
3. 发布纪律:本周发布 N 条(目标 7),没发布成功的日子和原因;公开作品 N 条、私密 N 条。
4. 本周作品数、周播放、涨粉最多的一条和播放最高的一条(车型、标题、播放、涨粉)。
5. 搜索:公开作品的搜索占比和推荐页占比各是多少(逐条或中位数);推荐页占比有没有哪条超过 10%(超过就点名,这是推荐开始给量的信号)。
6. 横竖屏对照(2026-11-13 起):横屏和竖屏各发了几条、各自的中位播放。每组不到 3 条就写"样本不够,不下结论"。满两周(2026-11-27 之后的第一个周一)给出结论:哪种中位播放高出 30% 以上就建议保留哪种,否则写"差别不明显,按制作成本选竖屏"。
6b. **两线对照表**(2026-11-17 起每周都写):两行(原理拆解 / 搜索向),列为 本周发布条数、播放中位、推荐页占比中位、5 秒完播、条均涨粉。推荐页占比用第 2 步 c 读到的;其余用 works 按 theme 分组算。某一行不到 3 条就在该行写"样本不够"。
   再写原理拆解的验证进度:「已发满 72 小时 N / 8 条」和 goals_by_theme.mechanism 的 verdict。发满 8 条的那一周给结论,照下面三选一写,不要自己发明第四种:
   - 四项都过线 → 建议节奏调成每周 5 条原理拆解 + 2 条搜索向,继续扩部件动画。
   - 推荐页占比过了(中位 ≥ 30%)但条均涨粉 < 3 → 建议改结尾预告、合集、置顶和主页简介,片型不动。
   - 8 条的推荐页占比中位仍 < 10% → 建议停掉这条线,请用户重新选方向(备选:40–90 秒的用车冷知识短片)。
7. 留人三项现在的值和目标(中位播放 ≥ 300、2 秒跳出 < 30%、5 秒完播 > 45%),以及 conversion 的主页访问和转化率。
8. 所处阶段和结论:
   - 阶段 1(goals.hold 为 true,或三项没全达标):只记录,不建议改打法。
   - 阶段 2(三项都达标):重点看主页访问 → 关注;建议用户把 `.env` 的 `TEAM_DAILY_SLOTS` 提到 2(只建议,不改)。
   - 复查点:2026-11-23 之后的第一篇周报,如果中位播放仍低于 100,或推荐页占比仍全部低于 5%,明确写出"建议用户决定:是否试少量 DOU+ 定向汽车兴趣人群,或本人配音开头"。
9. 粉丝兴趣前 6 和上周比有没有变化(第一次就只记录)。
10. 需要人的事:账号暂停、登录态失效、服务起不来、一周发布不到 5 条、私密作品数量、服务不通。
