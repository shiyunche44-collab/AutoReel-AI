# 团队闭环值守手册(定时 Claude 任务用)

目标:替人做"选题闸 / 门禁挂起 / 成片闸 / 失败重做",让一个选题循环
选题 → 制作 → 审核 → 打回 → 重做 → 审核 → 发布,**直到发布才算结束**。
超过返工上限(`TEAM_MAX_REVISIONS`,默认 2)的题标记「已放弃」,主编下一轮自动补新题。

**每天的目标**:有一条作品真正发布(计划 `published`),并且「成片待审」没有积压。
2026-11-12 实测这个号 90% 以上的播放来自搜索,所以每天稳定发一条、标题能被搜到,比什么都重要。

和定时任务提示词冲突时,以 `autoreel-team-loop` 的提示词为准(这份手册是它的补充说明)。

> **2026-11-13 起的变更(以此为准,下文与之冲突的段落作废):**
> `autoreel-team-loop` 改成「每日终审与发布」,每天 12:30、17:30 各跑一次,**单轮不循环**,不写心跳、不等渲染。
> 下面这些已由服务接手,会话不再做:拉起服务(开机自启 + 看门狗 `scripts/install_autostart.ps1`)、
> 失败重开、门禁被拦再试、发布网络失败重排、返工题排期、横竖屏对照的星期改写(`.env` 的
> `TEAM_LANDSCAPE_WEEKDAYS` / `TEAM_LANDSCAPE_UNTIL`)、成片机审(`app/pipeline/cut_review.py`,
> 结论在 `/api/team` 卡片的 `review.machine_review`,不合格的自动打回)。
> 会话只做:读机审结论 → 核提示项 → 发布或打回;把关 proposed 的选题。服务不通时只记录,**不自己启动服务**。
> `autoreel-morning-kickoff` 已停用。当前提示词副本见 `docs/scheduled-tasks/autoreel-team-loop.md`。

## 触发与防重入

- 每天 12:30、17:30 各触发一次,**单轮不循环**:不写心跳、不等渲染、不 ScheduleWakeup。
  一次会话最多审 2 条成片。

## 安全边界(硬规则)

- 只调用 `http://127.0.0.1:8848` 上的 `/api/team/*` 和 `/api/publish/{id}/retry`。
  先探测 `curl --noproxy '*' -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8848/`。不是 200 等 60 秒再试一次,
  仍不通就在日志写"服务不通(看门狗 5 分钟内会重启,见 data/logs/watchdog.log)"并结束。
  **不自己启动服务**:看门狗(计划任务 `AutoReel-AI-Server`,`scripts/install_autostart.ps1` 注册,
  登录时 + 每 5 分钟跑 `ensure_server.ps1`)负责拉起和重启卡死的服务。
  不运行 `scripts/serve.ps1` / `ensure_server.ps1`、不手动 `python run.py`、不杀端口、不换端口。
- 不调 `/advance`(与调度器抢写会损坏 mp4)、不改 `.env`、不删数据、不碰 `accounts/{id}/resume`
  (限流暂停的账号留给人)、不改作品权限(公开 / 私密)。
- 不确定的事不替人决定:写进日志"需要人",不要硬批。

## 每一轮做什么

1. **选题闸**(`status=proposed`):看 subject / angle / hook / evidence / heat、`slot_at` 是否未过期、
   和近期已发/在做的是否重复(同车型冷却期内不批)。
   合格 → `POST /api/team/plan/{id}/approve`;不合格 → `POST .../reject` 带 `{"note": 具体原因}`。
   - **车名**:subject 是完整、常用的车名(品牌 + 车系,如「比亚迪元UP」),hook / angle 里出现车名。
   - **搜索意图优先**:①「A 和 B 对比」(对手取同级热销车,两个车名都写出来);
     ②「车名 + 该不该买 / 能不能买 / 慎选」;③「车名 + 落地价 / 怎么选 / 哪个版本」。
   - 只讲单一配置细节、且车型不在热度榜前列的小众话题一律驳回。
   - 同一时间只保留 1 条"活链",一天最多批 3 个新题(不含返工)。
   - **横竖屏对照实验(2026-11-13 起两周)**:`slot_at` 落在周一、三、五的单车型条目(还没开工的),
     用 `PATCH /api/team/plan/{id}` 改成 `{"theme":"buyguide","aspect":"16:9","duration":240,"hook":"<车名>,到底该不该买?"}`;
     其余日子竖屏 9:16、60 秒左右。已开工的不改,每条只改一次。结论由周一的 `douyin-1000-weekly` 给。
   - **细分连更「一次讲透」(`theme=walkthrough`,横屏 240 秒)**:`.env` 的 `TEAM_WALKTHROUGH_WEEKDAYS`
     (逗号分隔,0=周一;默认空 = 不排)命中的日子,主编直接从 `auto_long.yaml` 的 `vocab.segments.offroad`
     名单里按顺序排一台硬派越野 / 皮卡,不问 LLM、不看热度榜前 10,一天一条。这类条目**不要 PATCH 改片型、
     画幅、时长,也不要因为"车不在热度榜"驳回**;其余审题标准照旧。名单全在冷却期时当天空档回到常规选题。
2. **门禁挂起**(有 `hold`):读原因。能自己解决(重试即可、素材问题已被后续版本排除)就
   `POST .../retry-gate`;额度用完(PAUSED_BUDGET)或同一条连续 2 次被拦 → 记"需要人",不再重试。
3. **成片闸**(`status=review`):
   - 看合规检查单(`/api/team` 里该条的 checklist),**有红项一律不通过**。
   - 跑成片 QA 脚本(逐帧 + 音频,见 `scripts/`),用 ffmpeg 抽关键帧(开头 3 秒、每拍中点)看图:
     画面与旁白对得上、素材不过时、无乱码/无关画面、字幕无错字、数字有来源、封面标题合规。
   - 通过 → `POST .../publish`,body 用卡片给的默认账号,带 `publish_at`,必要时带 `title`。
     - 标题:默认标题已以完整车名开头就不改;否则改写成「<完整车名>,<原来的判断句>」
       (对比片「<车A>和<车B>对比,<判断>」),不超过 30 字,不新增数字,不用绝对化词。
       接口因标题返回 400 → 去掉 `title` 用默认标题重发一次,记"需要人:标题没带车名"。
     - 今天要发的那条:早于 18:15 排今天 18:30,否则"现在 + 15 分钟";落在 23:00–08:00 就顺延到 08:30 之后。
     - **积压缓冲**:今天已发布(或已排今天)之后,继续审其他待审成片,每天最多再审 2 条;
       通过的排到从明天起第一个还没排片的日子 18:30,最多排到 3 天以后。
   - 不通过 → `POST .../reject-cut`,body `{"note": "具体意见", "redo": true, "bad_ranges": [[起,止],...]}`。
     意见要具体到"哪一段、什么问题、怎么改";能定位时间段就带 `bad_ranges`,新版会自动排除这些时间段用到的素材。
   - 返回里 `redo_stopped` 非空 = 到返工上限,该题已「已放弃」,不要再对它做任何事。
4. **失败接力**(`status=failed`,**第二阶段才开**):制作失败 / 发布被拒 →
   `POST .../redo`(body `{"note": 原因}`);发布任务本身的网络类失败先 `POST /api/publish/{pub_id}/retry`。
   已重做过的会返回 400,忽略即可。
5. **收尾**:往 `docs/team-loop-log.md` 追加一段:时间、批了几条、打回几条(附理由)、放弃几条、需要人的事。
   本轮什么都没发生就**不写、不输出**。

## 分阶段启用

- 第一阶段(刚启用的 1-2 天):只做 1-3,不碰 failed 的重做;每轮日志要写清判断依据,方便人抽查。
- 第二阶段:确认判断靠谱后再开第 4 步。

## 已知限制

- `uploading` 状态卡死(进程在上传中崩溃)没有自动恢复,避免重复发布(曾出现一条片子发 4 遍)。
  发现发布任务长时间 `uploading` → 记"需要人"。
- 看不到视频声音以外的细节时,宁可打回重做,不要放行。
